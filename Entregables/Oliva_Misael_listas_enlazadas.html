📐 Patrón MVT (Model-View-Template)

Django implementa MVT, una variante de MVC

Model - Lógica de Datos y Negocio

# models.py
class Producto(models.Model):
    nombre = models.CharField(max_length=200)
    precio_venta = models.DecimalField(max_digits=10, decimal_places=2)
    
    def get_stock_total(self):
        # Lógica de negocio encapsulada
        return self.lotes.aggregate(total=Sum('cantidad_actual'))['total']

View - Controlador de Lógica

# views.py
class ProductListView(ListView):
    model = Producto
    template_name = "stock/product_list.html"
    
    def get_queryset(self):
        # Filtrado y procesamiento de datos
        return Producto.objects.filter(is_active=True)

Template - Presentación (HTML)

Renderiza los datos procesados por la View (HTML + Template Tags).

⭐ Decisión Técnica Crítica: Sistema de Lotes

¿Por qué NO almacenar stock directamente en Producto?

❌ Enfoque Tradicional (Problemático)

class Producto(models.Model):
    nombre = models.CharField(max_length=200)
    stock = models.IntegerField()  # ❌ Simplista
    # Problemas:
    # - No maneja fechas de vencimiento
    # - No rastrea origen de mercadería
    # - No permite FIFO/FEFO

✅ Nuestro Enfoque: Sistema de Lotes

class Producto(models.Model):
    nombre = models.CharField(max_length=200)
    # NO tiene campo stock directo
    
    def get_stock_total(self):
        # Stock calculado dinámicamente
        return self.lotes.aggregate(total=Sum('cantidad_actual'))['total']

class Lote(models.Model):
    producto = models.ForeignKey(Producto, related_name='lotes')
    cantidad_actual = models.DecimalField(max_digits=10, decimal_places=3)
    precio_compra = models.DecimalField(max_digits=10, decimal_places=2)
    fecha_vencimiento = models.DateField(null=True, blank=True)

Ventajas:

  1. Trazabilidad: Cada ingreso de mercadería queda registrado.
  2. Gestión de Vencimientos: Control por lote individual.
  3. Cálculo de Rentabilidad: Precio compra vs. precio venta.
  4. FIFO/FEFO: Ordenamiento automático por fecha.

🔐 Autenticación y Autorización

Sistema de Usuarios Personalizado

# Extendemos AbstractUser de Django
class Usuario(AbstractUser):
    email = models.EmailField(unique=True)
    nombre_completo = models.CharField(max_length=150)
    rol = models.ForeignKey(Rol, on_delete=models.SET_NULL, null=True)
    
    USERNAME_FIELD = 'email'  # Login con email, no username
    
    def save(self, *args, **kwargs):
        # Lógica de permisos automática
        if self.rol and self.rol.nombre in ['Administrador', 'Vendedor']:
            self.is_staff = True
        super().save(*args, **kwargs)

Características:

  • Autenticación basada en Email (más moderno que username).
  • Sistema de Roles dinámico (no hardcodeado).
  • Permisos automáticos según rol asignado.
  • Contraseñas hasheadas (PBKDF2 por defecto).
  • Protección CSRF activa.

🎨 Vistas - Class-Based Views (CBV)

Ventaja de CBV: Reutilización y DRY (Don't Repeat Yourself)

# Django proporciona vistas genéricas potentes
class ProductListView(ListView):
    model = Producto
    template_name = "stock/product_list.html"
    context_object_name = 'productos'
    
    def get_queryset(self):
        # Personalización: filtrado por estado activo
        queryset = super().get_queryset()
        if self.request.GET.get('mostrar_ocultos'):
            return queryset.filter(is_active=False)
        return queryset.filter(is_active=True)
    
    def get_context_data(self, **kwargs):
        # Inyección de datos adicionales al contexto
        context = super().get_context_data(**kwargs)
        context['filterset'] = ProductFilter(self.request.GET, queryset=self.get_queryset())
        return context

Tipos de CBV utilizados:

  • ListView - Listado de objetos con paginación.
  • CreateView - Formularios de creación.
  • UpdateView - Formularios de edición.
  • DeleteView - Confirmación de eliminación.

🔍 ORM de Django - Abstracción de Base de Datos

Consultas Complejas sin SQL Directo

Ejemplo 1: Agregación

def get_stock_total(self):
    total = self.lotes.aggregate(total_stock=Sum('cantidad_actual'))['total_stock']
    return total if total is not None else 0

Ejemplo 2: Filtrado con relaciones (JOIN implícito)

productos_bajo_stock = Producto.objects.annotate(
    stock_total=Sum('lotes__cantidad_actual')
).filter(
    stock_total__lt=F('stock_minimo'),
    is_active=True
)

Ventajas del ORM:

  • Portabilidad: Cambiar de SQLite a PostgreSQL sin cambiar código.
  • Seguridad: Protección contra SQL Injection automática.
  • Optimización: Lazy loading, select_related, prefetch_related.
  • Migraciones: Control de versiones del esquema de BD.

🔄 Manejo de Transacciones y Consistencia

    Garantiza que TODA la venta se procese o NADA se procese.

    """
    # 1. Crear la venta
    venta = Venta.objects.create(...)
    
    # 2. Crear detalles y descontar stock
    for item in productos_vendidos:
        DetalleVenta.objects.create(...)
        
        # 3. Descontar del lote más antiguo (FIFO)
        descontar_stock_de_lotes(item.producto, item.cantidad)
    
    # 4. Calcular total
    venta.total = ...
    venta.save()
    
    return venta

Conceptos aplicados:

  • Atomicidad: Todo o nada.
  • Consistencia: Estado válido siempre.
  • Aislamiento: Transacciones concurrentes no interfieren.
  • Durabilidad: Cambios persistentes.

🎓 Conclusiones Técnicas

Decisiones de Diseño Justificadas

1. Django como Framework

  • Pro: "Batteries included" (ORM, Admin, Auth) acelera el desarrollo.
  • Pro: Seguridad por defecto (CSRF, SQL Injection).
  • Contra: Monolítico (mitigado con arquitectura de apps modulares).

2. Sistema de Lotes vs Stock Directo

  • Decisión crítica que diferencia un sistema amateur de uno profesional.
  • Permite trazabilidad completa y gestión de vencimientos.
  • Base para futuras funcionalidades (rentabilidad por lote, FIFO).

3. Class-Based Views (CBV)

  • Menos código, más mantenible a largo plazo.
  • Trade-off: curva de aprendizaje inicial mayor que vistas funcionales.

4. Soft Delete

  • Esencial para auditoría, cumplimiento normativo y recuperación de datos.
